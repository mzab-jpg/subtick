## What's actually wrong (plain English)
Your Cloud Functions send events and Google replies "OK" — but the events are silently thrown away because of a **format mismatch**: you're sending "app-style" events to a "web-style" address. Google accepts the envelope but drops the contents. There are also smaller bugs (wrong identifier, number-vs-text fields) that guarantee nothing shows up. I'll fix all of it and add a way to *prove* events are valid before going live.

### 2. `firebase/functions/src/analytics.ts` — the core fix (rewrite)
- **Switch URL**: `?firebase_app_id=...` → `?measurement_id=G-XXXXXXX&api_secret=...` (correct Web-stream format).
- **Switch body field**: `app_instance_id` → `client_id` (Web-stream field).
- **Fix payload types**: `engagement_time_msec: '1'` (string) → `1` (number); remove the misplaced per-event `timestamp_micros` (let GA4 auto-timestamp).
- **Stop using the Auth UID** as the identifier. Add a `resolveClientId()` helper: accept the client's 32-hex UUID, else mint a random per-request id (so events still land unattributed) — never the Auth UID.
- **Drop the now-unused `fallbackUserId` parameter** from `sendGAEvents`, and make `sendGAUserProperties` take `clientId` instead of `userId`.
- **Add debug mode** via `GA_DEBUG=true`: POSTs to `https://www.google-analytics.com/debug/mp/collect` and logs Google's `validationMessages` response. Default off. This is how we prove the fix (the normal endpoint never reports errors).
