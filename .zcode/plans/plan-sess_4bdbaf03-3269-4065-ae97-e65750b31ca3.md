## Plan: Add Matrix Mode to simulator.html

A new mode that ends the manual "change one value, record, repeat" loop by running the cross-product of **controllable settings × user-behaviour scenarios** in one pass and showing the robustness landscape visually.

### 1. Refactor: extract `runSimCore(config, opts)`
- Collapse the two duplicated day-loops (`processDay` line 407, `pd2` line 512 — confirmed behaviourally identical by exploration) into one reusable function.
- Signature: `runSimCore(config, { captureSamples, captureCsv, onProgress }) → simData`
- Rewire `runSimulation()` and `runSweep()` to call it. Deletes ~80 lines of duplication; guarantees matrix uses identical algorithm.
- Preserve all existing behaviour (CSV chunks, sampleEvents capture, progress UI) behind the option flags.

### 2. New "🔀 Matrix Mode" control panel
Inserted after the existing Sweep panel (line ~103), matching its collapsible `.sweep-group` style:
- **User scenarios (rows)**: 5–6 preset populations (Engaged, Passive/Skim, Quick-exit-heavy, Discovery-prone, Conservative) defined as behaviour-rate overrides on a base config. Editable.
- **Candidate settings (columns)**: picker for which controllable knob to vary (score weights / feedback deltas / learning rates / tranche / decay / trending-quality) and N levels. Start with score-weight blends since that's the highest-leverage knob.
- **Composite-score weighting**: 4 sliders (Personalization, Quality, Discovery, Balance) with balanced defaults — tunable, not hard-coded.
- **Seed field**: PRNG seed so matrix cells are comparable (currently no reproducibility). Implement a seeded RNG (`mulberry32`) threaded through `gauss`/`shuffle`/`Math.random` calls within matrix runs only.
- **▶ Run Matrix** button + progress indicator.

### 3. New matrix results view
Inserted after `#sweepResultsContainer` (line 253), following the same hidden-until-run pattern:
- **Heatmap** (new `drawHeatmap(ctx, matrix, …)` canvas helper — reuses existing `drawAxis` idiom + palette): rows = user scenarios, columns = candidate settings, cell colour = composite score. The headline "see the landscape" chart.
- **Robustness bars**: per candidate setting, bars showing its score across all scenarios; spread = fragility. Lets you pick the robust winner.
- **Per-metric breakdown**: small-multiples heatmaps (one per P / T / R / Q / discovery / quality) so you see *which* metric drives each cell, not just the blend.
- **Click any cell** → all 13 existing charts (`drawPScoreChart`, `drawDominantChart`, … `drawUserInspector`) redraw for that run's `simData`. Reuses `displayResults()` unchanged. Keeps the deep-dive you already have.

### 4. Composite score definition
Normalized blend of final-day metrics from `simData.dailyMetrics[last]`:
- **Personalization**: `avgP` (0–1) + `dom.P / count` (P-dominant share)
- **Quality**: `trancheCounts.high / count` + publisher-quality drift magnitude
- **Discovery**: `avgPubs` (feed diversity) normalized + `trancheCounts.tail / count` (tail share — serendipity) + user weight-spread (users are differentiated)
- **Balance**: penalty if any one of P/T/R/Q dominance > 70% or < 10%
Each component normalized to 0–1, blended by slider weights, renormalized.

### 5. Performance budget
- Per-cell: 200 users × 7 days (matches existing sweep budget).
- Worst case 6 scenarios × 5 settings = 30 cells ≈ 30× a sweep step. Inside ~10 min on modest hardware via existing `setTimeout(0)` yielding.
- Live progress: "Cell 7/30: scenario × setting …" with progress bar.
